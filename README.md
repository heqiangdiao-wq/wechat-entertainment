# 微乐盒子 WeFun Box

> 微信娱乐项目 · 施工中 🚧

一个面向微信场景的娱乐工具合集：群聊小游戏、表情包机器人、互动抽奖与整活助手。

## 项目简介

微信群不缺人，缺的是"把一群人逗起来"的工具。微乐盒子想做的是一套**开箱即用、本地运行**的微信娱乐组件：

- **好玩**：消息驱动的轻量小游戏，30 秒上手，不用装 App；
- **省事**：改一个 YAML 配置就能跑，不依赖云端服务；
- **干净**：不收集群聊内容，不做诱导分享，不碰任何灰产功能。

它**不是**什么：不是外挂，不是营销裂变工具，不是"爆粉"神器——这些明确不做。

## 功能规划

| 模块 | 一句话说明 | 状态 |
|---|---|---|
| `games` 群聊小游戏 | 你画我猜 / 谁是卧底 / 数字炸弹，消息即指令 | 📋 规划中 |
| `emoji` 表情包机器人 | 表情检索、GIF 转微信表情、斗图计分 | 📋 规划中 |
| `lottery` 抽奖签到 | 群抽奖、打卡积分、日榜周榜 | 📋 规划中 |
| `fun` 整活助手 | 复读机、关键词自动回复、群语录 | 📋 规划中 |

优先级：`games` → `emoji` → `lottery` → `fun`。先把一个模块做透，再开下一个。

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.12+ | 生态成熟，团队熟悉 |
| 微信侧自动化 | Playwright（驱动微信 PC 客户端） | 不注入 DLL、不改协议，稳 |

## 消息协议设计

所有交互通过群聊消息驱动，统一指令格式：

| 元素 | 规则 | 示例 |
|---|---|---|
| 前缀 | 默认 `/`，可配置 | `/开始` |
| 指令名 | 小写字母与数字，2-12 字符 | `bomb` |
| 参数 | 空格分隔，`key=value` 或位置参数 | `/bomb 人数=8` |
| 回复 | 普通文本回复并 @ 发起人 | @张三 游戏已创建 |

消息总线流程：

```text
微信消息 → 监听器 → 指令解析 → 插件路由 → 游戏状态机 → 渲染器 → 发送
```

设计原则：

- **无状态指令**（帮助、积分查询）直接回复；**有状态指令**（游戏中）走状态机；
- 每个群一个独立游戏上下文，群与群之间互不干扰；
- 指令冲突时先到先得，后到的收到"游戏已在进行中"提示。

## 游戏规则：数字炸弹

**人数**：3-20 人　**时长**：2-5 分钟　**指令**：`/bomb`

**流程**：

1. 发起人发送 `/bomb`，机器人随机生成 1-100 的秘密数字；
2. 玩家轮流猜数，机器人回复"大了"或"小了"；
3. 猜中者引爆炸弹，本局结束，按约定接受惩罚（如发一个表情包）；
4. 可选玩法：把上局猜错次数最多的玩家设为下局"炸弹手"。

**状态机**：

```text
idle → waiting(凑人) → playing(轮流猜) → exploded(结算) → idle
```

**防挂机**：60 秒未出猜数自动跳过该玩家；全体沉默 3 分钟自动解散，本局不计分。

## 游戏规则：你画我猜

**人数**：3-15 人　**时长**：5-10 分钟　**指令**：`/draw`

**流程**：

1. 发起人 `/draw` 从词库随机抽一个词（内置词库 + 自定义词库）；
2. 当前画家作画，以图片形式发到群里；
3. 其他玩家在群里猜词，猜中即得分，画家按剩余时间拿助攻分；
4. 时间到未猜中则公布答案，进入下一轮换人。

**计分**：猜中者 +10，画家 +5（有人猜中）/ 0（无人猜中）；连续两轮无人猜中自动换画家。

**边界**：每轮 90 秒；只接受群内图片消息，不拉取外部链接。

## 游戏规则：谁是卧底

**人数**：5-12 人　**时长**：8-15 分钟　**指令**：`/spy`

**流程**：

1. 系统分配身份：平民拿相同词，卧底拿相近词（如"牙膏"/"牙刷"）；
2. 每人轮流用一句话描述自己的词，不能直接说出词；
3. 自由讨论后投票，得票最高者出局；
4. 卧底全灭则平民胜；卧底存活到剩余人数 ≤ 2 则卧底胜。

**公平性**：身份由系统随机分配并私聊发送，不公开发布；词库按难度分级；平票时进入第二轮投票。

**边界**：描述禁止复读上家原句，机器人做简单相似度检查并提醒。

## 模块设计：表情包机器人

| 能力 | 指令 | 说明 |
|---|---|---|
| 表情检索 | `/emoji 关键词` | 内置表情库 + 本地收藏夹检索 |
| 斗图计分 | 自动触发 | 群内连续发表情包进入"斗图模式"，统计连击数 |
| GIF 转表情 | `/emoji2gif` | 把群内 GIF / 视频片段转成微信可用表情（≤ 240px） |

**边界**：

- 只索引本地与公开渠道表情，不抓取任何需登录的内容；
- 斗图计分仅存本地 SQLite，不上传；
- 凌晨 0:00-8:00 默认静音（可配置），避免打扰。

## 模块设计：抽奖与签到

**签到**：`/签到` 每日一次，积分 +1~+5（随机），连续签到有加成，断签重置连击。

**抽奖**：`/抽奖 奖品=奶茶一杯` 发起群抽奖：

- 参与：发送 `/参加` 或在抽奖消息下回复任意内容；
- 开奖：到截止时间或人数满，系统随机抽取并 @ 中奖者；
- 公平性：随机种子公开可复现（时间戳 + 群号 + 抽奖 ID），任何人可验；
- 防刷：同一用户多次参与只计一次；管理员可取消并重抽。

**榜单**：`/榜单 日|周` 查看积分榜，数据仅存本地。

## 配置参考

`config/config.example.yaml` 完整示例：

```yaml
wechat:
  listen_groups: []          # 监听的群名，空 = 全部（需在 UI 层勾选）
  reply_at_sender: true      # 回复时 @ 发起人

command:
  prefix: "/"                # 指令前缀
  aliases:                   # 指令别名
    bomb: [bz, 炸弹]
    draw: [你画我猜]

games:
  bomb:
    range: [1, 100]          # 秘密数字范围
    idle_timeout_sec: 60     # 挂机超时
  draw:
    round_sec: 90
    word_pack: builtin/cn-common

points:
  sign_base: 2               # 签到基础分
  sign_bonus_streak: 3       # 连签 N 天起每天 +1

privacy:
  store_chat_log: false      # 是否记录群聊日志（默认否）
```

**所有配置项都有默认值**，删掉任何一行都能以默认配置启动。

## 架构说明

```text
┌─────────────────────────────────────────┐
│  adapters/   微信适配层（Playwright 驱动） │
├─────────────────────────────────────────┤
│  core/       消息总线 · 指令解析 · 插件加载 │
├─────────────────────────────────────────┤
│  plugins/    games / emoji / lottery / fun │
├─────────────────────────────────────────┤
│  store/      SQLite（积分/签到/对局状态）   │
└─────────────────────────────────────────┘
```

**三条架构纪律**：

1. **适配层可替换**：换成影刀 RPA 或未来的协议方案时，`plugins/` 零改动；
2. **插件无特权**：插件只能通过 core 提供的 API 收发消息，不能直接碰微信窗口；
3. **状态可弃**：SQLite 里除积分外都是可重放数据，删掉不影响下次启动。

## 测试策略

| 层 | 测什么 | 怎么测 |
|---|---|---|
| 指令解析 | 前缀/别名/参数边界 | pytest 参数化，纯函数无 IO |
| 游戏状态机 | 流转与非法跳转 | 状态机单测 + 随机序列 fuzz |
| 计分 | 积分加减与连击 | 快照对拍，边界值（0、负数、上限） |
| 端到端 | 真实群聊闭环 | 手动剧本，见 `docs/e2e-scripts.md` |

**原则**：能纯函数测的不起进程；能离线测的不连微信。微信适配层只做冒烟测试（人工跑剧本），不写自动化断言——UI 变化太快，自动化只会天天误报。
